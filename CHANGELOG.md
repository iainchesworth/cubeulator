# Changelog

All notable changes to this project are documented in this file, in the
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. This
project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed

- The system tests no longer take over the desktop they are run from. The
  committed test presets exclude the `system` label, so a plain
  `ctest --preset <preset>` never opens a window; the suite is run with the
  matching `<preset>-system` preset (CI's system legs use it). Where the
  platform allows it (`CUBEULATOR_PLATFORM_TEST_HIDE_WINDOW`, Windows today) the
  window the suite drives is fully transparent, click-through and never
  activated - still shown, exposed and rendered, and no longer holding the
  foreground for the length of a run - and `CUBE_SYSTEM_TEST_VISIBLE=1` puts it
  back on the desktop to watch a case
  ([docs/testing.md](docs/testing.md#system-tests)).

- Platform isolation: the operating system is now decided in one place
  (`cmake/Platform.cmake`) and everything a platform contributes - sources,
  libraries, defines, deploy and packaging steps - is declared in
  `src/app/platform/<name>/platform.cmake`. No first-party source file contains
  a preprocessor conditional, an OS header outside the platform section, or a
  runtime OS test; the `platform-isolation` CI job holds that. See
  [docs/platform-isolation.md](docs/platform-isolation.md). Two user-visible
  consequences: the version block's `target:` line is now stamped by CMake
  (MSVC's compiler number is unchanged; a missing compiler reads
  `unknown compiler` as before), and the Android manifest moved to
  `src/app/platform/android/package/`.
- Every tool CI uses is pinned exactly (CMake, Ninja, NSIS, gcovr, zizmor, the
  docs toolchain) and the actions are at their newest release that is at least
  a week old ([docs/ci.md](docs/ci.md)).
- The desktop shell follows the platform-isolation rule: keep awake, the
  process identity and the window traits are one implementation per platform
  behind `interfaces/desktop_shell.hpp`, and each platform's packaging CMake is
  reached from its fragment (`packaging/<name>/`), so no shared file tests the
  OS ([docs/platform-isolation.md](docs/platform-isolation.md)).

### Removed

- bgfx, and everything that existed only for it. It was declared in
  `vcpkg.json` but nothing linked it: the `cube::gpu_render` target
  (`src/render`) was one empty function, and the cube is drawn by Qt Quick 3D
  and the QML Canvas. Gone with it: the lib-side `cube::render` stub, the
  `gpu_surface` platform interface and its five per-OS implementations, and the
  `gpu_surface_unavailable` / `shader_compile_failed` error codes. vcpkg no
  longer builds seven ports (bgfx, libsquish, lodepng, mgnlibs, miniz, stb,
  tinyexr) on any leg, and `find_package(bgfx)` is no longer a configure-time
  requirement. See [docs/architecture.md](docs/architecture.md#gpu-rendering).

### Added

- Desktop packages for Windows (NSIS installer), macOS (`.dmg`) and Linux
  (`.deb`, `.rpm`), each with the app icon, the version, the identifier
  `com.iainchesworthlabs.cubeulator` and the third-party notices; built and
  checked in CI on every push, and attached to a draft GitHub Release by the
  `Release` workflow on a version tag ([docs/packaging.md](docs/packaging.md),
  [docs/releasing.md](docs/releasing.md)).
- Window manners on all three desktops: 960 x 680 default, 360 x 560 minimum,
  remembered size, position and maximised state, a position off every screen
  ignored; keyboard shortcuts for Settings, Help, a new scan, full screen and
  quit; the macOS menu bar; a `KeepAwake` helper (wired to nothing yet).
- App icons rasterised from `docs/design/identity/` at build time.
- Tracy profiler instrumentation, the same as the rest of the application
  family: `cube/profiling.hpp` macros (zones, frames, plots, messages) behind
  `CUBEULATOR_ENABLE_TRACY` and an opt-in `profiling` vcpkg feature, with
  `*-profiling` presets. The capture thread, the direct scan and held-cube
  reads, the recorder, startup, the Qt Quick frame and every solver stage are
  instrumented; off by default and compiled to nothing. See
  [docs/profiling.md](docs/profiling.md).
- Third-party notices generated by the build (`cmake/ThirdPartyNotices*.cmake`,
  `third_party/notices/`): the shipped components, their licences and texts,
  embedded as `:/licences/*` and installed with every desktop package; a
  CTest case fails when something that ships has no notice. Licence inventory
  and the Qt/App Store options paper in [docs/licensing.md](docs/licensing.md).
- Repository skeleton: folder layout, CMake build system (presets, warnings,
  sanitizers, coverage, packaging), vendored vcpkg submodule, CI/security
  workflows (CodeQL, OSV-Scanner, Zizmor, Scorecard, dependency review),
  mkdocs documentation site, and stub `cube::lib`/`cube::platform`/
  `cube::gpu_render` targets. No solver, computer vision, edge-AI, or
  rendering logic yet — see [Architecture](docs/architecture.md).
