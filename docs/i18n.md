# Translations

How Cubeulator is made translatable, and how it is kept that way. This is the
plumbing (workstream E2b of [the app experience plan](app-experience-plan.md)).
The translations themselves are E5's; the wording they translate is
[`design/content.md`](design/content.md) and
[`design/strings.json`](design/strings.json).

The set at first release is **nine languages**: English, German, French,
Spanish, Japanese, Simplified Chinese, Hebrew, Arabic and Yiddish. Three are
written right to left. The source language is British English.

## How it fits together

```
docs/design/strings.json          id, British English, note for translators, plural forms
src/app/i18n/languages.json       the nine languages, their plural forms, their direction
        |
        |  tools/i18n/strings_to_ts.py --write
        v
src/app/i18n/translations/cubeulator_<code>.ts      one id-based catalogue per language, committed
        |
        |  lrelease -idbased -nounfinished   (src/app/CMakeLists.txt, cube_app_i18n)
        v
:/i18n/cubeulator_<code>.qm       embedded in the app
        |
        |  cube::i18n::LanguageManager (src/app/qt/i18n/)
        v
qsTrId("some.id") in QML          what a person reads
```

- **`strings.json` is the only place a string is written.** Its ids, English,
  notes and plural forms are copied into every catalogue by
  `tools/i18n/strings_to_ts.py`; a test and a CI step fail if a catalogue is
  not what that script would write. A translator's work is kept: the script
  merges by id and never writes a translation of its own.
- **Strings are keyed by id**, not by their English (`family.md` D5). Rewording
  the English does not touch a translation. A string whose *meaning* changes
  gets a new id.
- **English is installed under every language.** A string with no translation
  yet - all of them, in eight of the nine, until E5 - shows its English. That
  is also what makes "a raw id on the screen" impossible for any id the
  catalogue has, and a test holds it (below).

## Writing a string in QML

```qml
Text { text: qsTrId("home.lede") }                         // a whole string
Text { text: qsTrId("home.resume.body").arg(turn).arg(total) }   // "Turn %1 of %2"
Text { text: qsTrId("review.status.partial", count) }      // a plural: "%n sticker to go"
```

- **Always `qsTrId("id")`, with a literal id.** Not `qsTr`, not a string
  literal, not an id built from pieces: the extractor, the lint and the tests
  can only see a literal.
- **Whole sentences.** Never `"Turn " + n + " of " + total`: a translator
  cannot reorder fragments. One string, `%1` and `%2` where the numbers go.
- **Wording belongs in QML, never in a controller.** A controller exposes a
  state or a code; QML says it (plan, "Contracts every lane keeps").
- **Capitals are the app's job.** A small-capital label is written in
  sentence case in `strings.json` and given `font.capitalization:
  Font.AllUppercase`, which is locale-aware.
- **Direction words never mirror** (`dir.left` is the physical left): do not
  swap them for a right-to-left language.

### Numbers, dates and times

The app's language sets the default `QLocale` (the operating system's does
not), so digits, separators and date formats follow the language the person
chose. In QML read the locale through `Qt.uiLanguage`, which makes the binding
update when the language changes:

```qml
Text { text: Qt.locale(Qt.uiLanguage).toString(AppState.moveCount) }
Text { text: Qt.locale(Qt.uiLanguage).toString(date, Locale.ShortFormat) }
```

In a plural string the count is written `%Ln` in the catalogues (`strings.json`
keeps `%n`; the script converts), which Qt formats with that locale. Arabic
shows Arabic-Indic digits; notation letters, key names and version numbers
never go through it.

## Adding a string

1. Add it to `docs/design/strings.json`: `"group.name": ["English", "Note for
   the translator"]`. A plural is `{ "one": "...", "other": "..." }` with `%n`.
   Say in the note where it appears and what a placeholder is.
2. `python tools/i18n/strings_to_ts.py --write` and commit the nine `.ts`
   files with it. (`docs/design/tools/build.py` regenerates the inventory in
   `content.md` and the prototype from the same file.)
3. Use it: `qsTrId("group.name")`.

To remove a string, delete it from `strings.json` and rerun the script; git
keeps what a translator wrote. To reword, edit the English in place. To
change what a string *means*, add a new id.

## Adding a language

1. Add an entry to `src/app/i18n/languages.json`: `code` (what is stored under
   `language/code`), `file`, `tag` (the `QLocale` name), `name` (the language
   in itself, never translated), `plurals` (the number of plural forms Qt's
   rule has for it - `lconvert` tells you, the table below shows the nine),
   `rtl`, `translated: false`.
2. `python tools/i18n/strings_to_ts.py --write`. The new catalogue is made
   with every entry unfinished; the app shows English for all of it.
3. Make the face for its script available to `Theme.qml` (the kit session's:
   see "What belongs to other branches"). Right to left is read from
   `rtl`; a test fails if it disagrees with Qt.
4. The translator fills the catalogue in Linguist or by hand. When it is
   finished and a fluent reader has been through it, set `translated: true`:
   from then on the translation tests require no unfinished entry in it.

| code | language | plural forms Qt has | direction | face |
|---|---|---|---|---|
| `en` | English | 2 | ltr | Archivo |
| `de` | Deutsch | 2 | ltr | Archivo |
| `fr` | Français | 2 (0 and 1 are the singular) | ltr | Archivo |
| `es` | Español | 2 | ltr | Archivo |
| `ja` | 日本語 | 1 | ltr | the system's, chosen by language |
| `zh-CN` | 简体中文 | 1 | ltr | the system's, chosen by language |
| `he` | עברית | 2 | **rtl** | Noto Sans Hebrew |
| `ar` | العربية | 6 (zero, one, two, few, many, other) | **rtl** | Noto Sans Arabic |
| `yi` | יידיש | 2 | **rtl** | Noto Sans Hebrew |

Qt's table gives Hebrew two forms (one, other); CLDR also has a dual. The
catalogue carries what `lrelease` will use, and the dual is said in the
plural's other form.

## What a translator needs to know

- **The id is the key** and never changes once a translation exists for it.
  The English and the note (`<extracomment>` in Linguist) are context, and the
  note says where the string is shown.
- **`%1`, `%2`** are arguments and may be reordered. **`%Ln`** is a count and
  the string has plural forms: supply every form the language has.
- **Never translated**: *Cubeulator*, the notation letters, key names.
- **Whole sentences**, no joining. The three parts of a turn are shown as
  three labels and are the one exception (`content.md`).
- **Design allows 40% more than the English.** The pseudo-locale takes all of
  it, so a layout that holds there holds a real translation.
- **Right to left**: write *left* and *right* as the physical left and right.
  The app does not swap them.

## The language manager

`cube::i18n::LanguageManager` (`src/app/qt/i18n/language_manager.{hpp,cpp}`)
is ICL Forge's `LanguageManager`
(`apps/shared/preferences/src/language_manager.*`, itself Countdown Solver's)
ported to ids. It is the `LanguageManager` singleton of the `Cubeulator` QML
module.

| | |
|---|---|
| start-up order | `CUBEULATOR_LOCALE` (a code, or `xx`), then the saved `language/code`, then the device, then English |
| the device | the first of `QLocale::system().uiLanguages()` the app has a language for; Traditional Chinese is not guessed at |
| the setting | `language/code`; absent means "same as this device" |
| `availableLanguages()` | `{code, name, rtl}`, English first, names in themselves; never the pseudo-locale |
| `deviceLanguage()` | `{code, name}` for the "Same as this device (%1)" row |
| `setLanguage(code)` | saves, installs the translators, sets the layout direction and default locale, retranslates the engine; false for a code the app does not have |
| `useSystemLanguage()` / `hasOverride()` | forget the saved choice / whether there is one |
| `preview(code)` | switches without saving and accepts `xx`: tests, the gallery, the tour |
| `currentLanguage`, `selectedLanguage`, `rtl`, `currentLanguageName` | what QML binds to |

What it adds to the family's: ids; English under every language; the default
locale (numbers and times follow the app's language); the device's *list* of
preferences; and it leaves the font to `Theme.qml`.

### The pseudo-locale

`CUBEULATOR_LOCALE=xx cube_app` shows every string accented, bracketed and 40%
longer: `[Scàn à cûbé ~~~~~ ~~]`. A string cut off loses its closing bracket; a
string with no brackets never went through an id lookup. It is generated from
the English by `strings_to_ts.py` (so it cannot drift) and is checked for
length and brackets by the tests.

### Right to left

`Main.qml` mirrors the layout when `LanguageManager.rtl` is true
(`LayoutMirroring` on the screen loader, inherited down): rows and anchors
reverse, panes change sides, the back control and chevrons turn round
(`Icon.qml`).

**Never mirrored** (`accessibility.md`): the cube - the 3D view, `CubeView`, a
side's nine stickers - the camera picture, direction arrows and the words
*left*/*right*, notation, key names, version numbers. `CubeView.qml` sets
`LayoutMirroring.enabled: false` on itself and its children; the 3D cube is
not affected by layout mirroring at all, and a test proves it (below). A
component that draws something of the object in the hand does the same.

Known limit, until E3a: in the legacy screens a `Column` has no layout
direction, so its children keep the column's left edge in a right-to-left
language. Panes, rows, anchors, button order and chevrons do mirror; the kit's
`KitPage` is what finishes it.

## The gates

Every one is a CTest entry (so they run on all three CI legs) and is listed
with what to do when it fails.

| gate | what it checks | when it fails |
|---|---|---|
| `i18n_catalogues_match_strings` | the nine catalogues and the pseudo-locale are what `strings_to_ts.py` writes from `strings.json` (the family's "rerun the update and fail on a diff") | `python tools/i18n/strings_to_ts.py --write`, commit |
| `i18n_no_unwrapped_literals` | no user-visible string literal in QML, and no sentence in a controller, that is not an id lookup; no `qsTr`; no sentence built from fragments. Per-lane allowlist, literal by literal | use `qsTrId`; add the string to `strings.json` if it has no id |
| `i18n_lint_selftest` | the lint fails on what it exists to catch and passes a converted file | fix the lint |
| `i18n_ids_in_code_exist` | every id the code asks for (found by Qt's own `lupdate`) is in `strings.json`; no id built from pieces | add it or fix the typo |
| `translation catalogue ...` (`cube_i18n_tests [catalogue]`) | same ids everywhere; the English is `strings.json`; notes carried; plural forms per language; nothing empty, unfinished or obsolete where a language says it is done; `%1` and the count kept; *Cubeulator* kept; the pseudo-locale longer and bracketed | the message names the language and the id |
| `a raw id never reaches the screen...` (`[runtime]`) | for every id in every language the result is not the id and not empty; and a control that with no catalogue it *is* the id, so the check can fail | an id missing from the English catalogue |
| `a language with no translation yet shows the English` | the fall-back, through the manager | |
| `every plural string resolves for every count ...`, `each language's plural rule picks the form its language has` | every plural has every form for every count, in the app's digits; Qt's rule (asked of `lrelease`) picks the CLDR form for each of the nine | |
| `language manager ...` (`[manager]`) | the set and its endonyms; aliases (`zh_CN`, `iw`); start-up order; one call changes strings, direction and locale together and saves `language/code`; refuses `xx` and unknown codes | |
| `cube_i18n_screen_tests` (`[screen]`) | a screen that is up switches en, pseudo-locale, he and back; the converted screens hold the pseudo-locale at both sizes without a string cut off, run off the window or out of its pane or button; the layout mirrors for he, ar and yi and returns; the cube view is not mirrored; the 3D cube is the solver's cube and every one of the 18 turns goes the solver's way in a right-to-left language | |

The tests run with the app's own controllers and QML (`cube_i18n_screen_tests`
loads the screens as items, as the solve lane's `cube_qml_tests` does). The
whole app, driven through its windows, is the system tests' (`tests/system`).

To look at a screen in a language, for whoever reviews it:

```bash
CUBE_I18N_SHOT_DIR=shots CUBE_I18N_SHOT_SCREEN=LaunchScreen CUBE_I18N_SHOT_LANG=xx \
    cube_i18n_screen_tests "[.shots]"
```

One picture a process (a second `grabWindow()` with the 3D cube crashed the
solve lane's gallery test).

## What belongs to other branches

Each lane's files are in [`i18n-lanes.md`](i18n-lanes.md), literal by
literal, with the id to use where the design has one. The lint's allowlist
(`tools/i18n/lint_allowlist.json`) names the owner of every entry; an entry
whose text has gone fails the lint, so the list can only get shorter.

### The kit session (`feature/ax-kit`)

`Theme.qml`, `SettingsState.qml` and font loading are the kit's. The seam:

- The manager **announces** the language and the direction; the kit **picks
  the face**. `Theme.qml` already derives `rtl`, `script` and `headingFamily`
  from `SettingsState.language`. Bind them to the manager instead:
  `Theme.rtl: LanguageManager.rtl`, and key the face by
  `LanguageManager.currentLanguage` (`he` and `yi`: Noto Sans Hebrew; `ar`:
  Noto Sans Arabic; `ja`, `zh-CN`: the system's).
- **One writer of `language/code`.** `SettingsState.language` is a
  `Qt.labs.settings` alias to the same key the manager writes. Make it read
  `LanguageManager.selectedLanguage` and write through
  `LanguageManager.setLanguage(code)` / `useSystemLanguage()`, so that a
  choice also switches the translators and the direction. Until then both
  write the same string, so nothing is lost.
- `KitWindowBindings` "mirrors the content by the language": use
  `LanguageManager.rtl`; `Main.qml` already does so for the legacy screens.
- `Qt.locale()` now answers in the app's language, so
  `Theme.languageTag`'s `Qt.locale().name` is correct as it is.
- The labels in `SettingsState` (theme, speed, shader style) are in
  `i18n-lanes.md`.

### Start-up and the system tests (`AppRuntime`, E0a)

Today `main.cpp` calls `cube::i18n::install(app, engine)` between
`addImageProviders` and `loadFromModule`. `feature/ax-system-tests` (E0a)
replaces that start-up with `AppRuntime`, which `tests/system` boots too, so
the call belongs in its constructor. Both branches change the same lines;
**whichever lands second** makes this change, and nothing else is needed for
the language cases to run:

1. `src/app/qt/app_runtime.cpp`: after `controllers_.addImageProviders(engine_)`,
   `cube::i18n::install(*qGuiApp, engine_);` (include `i18n/language_manager.hpp`
   and `<QGuiApplication>`). `main.cpp` keeps E0a's shape and loses its own call.
2. `src/app/CMakeLists.txt`: `target_link_libraries(cube_app_runtime PUBLIC
   cube_app_i18n)`.
3. The converted screens in E0a carry `objectName`s on the same lines this
   branch turned into `qsTrId()`: keep both. Its names (`launch.startScan`,
   `settings.language`, `settings.theme.<n>`, ...) are what the system tests
   find them by; the Settings language chips take `settings.language.<n>`,
   where 0 is "Same as this device" and 1 to 9 are en de fr es ja zh-CN he ar
   yi.
4. `tests/system/app.cpp`, `App::reset()`: the baseline includes the language.
   The sweeps press every control, language chips included, and the next test
   must not begin in Hebrew:
   ```cpp
   if (QObject* language = runtime_->engine().singletonInstance<QObject*>(
           "Cubeulator", "LanguageManager"); language != nullptr) {
       QMetaObject::invokeMethod(language, "preview", Q_ARG(QString, QStringLiteral("en")));
   }
   QSettings().remove(QStringLiteral("language/code"));
   ```
5. Two English strings in `tests/system/journey_test.cpp` are the design's now:
   "No camera was found. Plug one in, then look again." and "Cubeulator reads
   the cube with this camera."
6. `tests/system/layout_test.cpp`: the permission screen's phone entries leave
   the known list (`permission.notNow` at 375x667, 390x844 and 719x640,
   `permission.openSettings` at 375x667 and 390x844): this branch fixed them,
   and the case fails the day one is fixed.

`tests/i18n/system/language_test.cpp` is compiled into `cube_system_tests` by
`tests/CMakeLists.txt` when `tests/system` exists. It switches the language in
the real window (English, the pseudo-locale, Hebrew and back; and by pressing
the chips in Settings), holds the cube's picture the same when the pane around
it changes sides, checks that nothing is cut off or pushed below the window in
the pseudo-locale at both sizes on four screens, and holds every control to
the window in Hebrew with a known list (below). Its screenshots land in the
tour's directory as `language_*.png`.

Found by it, and not this branch's to fix: in a right-to-left language the
solve screen's `solve.rescan` is placed off the left edge of the window. It is
the solve lane's `SolveScreen.qml`; the known list in the test names it, so the
day it is fixed the test says to remove the entry.

### C++ that still words things

Controllers expose codes; QML turns them into text. One is named in the
plan:

- `DirectScan.cameraError` (`direct_scan.cpp`): the text is
  `cube::to_string(CubeError)` from `src/lib/include/cube/error.hpp`. Expose
  the enum's name (`camera_not_found`, `camera_start_failed`, ...) and word it
  in QML with `scan.camera.*`, which exist.

`AppState.elapsedLabel()` builds `mm:ss` from digits. Times are always left to
right, but the digits should be the language's: format with
`Qt.locale(Qt.uiLanguage)`. It is in `AppState.qml`, which E2a splits.

## What it does not do

- **It writes no translation.** E5 does; the catalogues are empty and fall
  back to English until then.
- **It does not choose faces.** See the kit.
- **The legacy screens are converted only where the design has a string.** The
  settings the design removes (cube motion, shader
  style) and the Method statistic stay literal and are on the allowlist under
  the experience lane; E3a/E3d delete them.
- **Qt's own catalogue** (`qt_<code>.qm`: standard buttons, dialogs) is
  loaded where Qt ships one. It has none for Yiddish.
