# Licences

Lane: experience. New (E3b). The list itself is generated by E0b.

The notices the app owes to the components it is built from, readable in
the app. Nothing here is written by hand: E0b generates the list and the
texts from what actually ships in each build, so that it cannot drift
when a dependency is added or removed.

Entered from: **About > Licences**.

## Layout

One scrolling column at every size, 24 margin, at most 640 wide, centred
from medium up. A top bar: back and the title.

## Parts

| part | component | string | objectName |
|---|---|---|---|
| Back | icon button | `common.back` | `licences.back` |
| Title | top bar title, heading level 1 | `licences.title` | `licences.title` |
| Introduction | `body`, `inkSecondary` | `licences.intro` | `licences.intro` |
| Cubeulator's own row | list row; value is its licence identifier | `licences.own` | `licences.own` |
| Component row | list row: the component's name, and its licence identifier as the value, in the mono face | - | `licences.row1` ... |
| Notice text | The component's copyright notice and licence, in the mono face on `surface`, in a block that wraps and can be selected. Always left to right | - | `licences.text` |
| Unavailable | notice, caution | `licences.unavailable.title`, `licences.unavailable.body` | `licences.unavailable` |

- Component names and licence identifiers (SPDX, such as `Apache-2.0`)
  are data from the build. They are not translated.
- **Notice and licence texts are never translated**, whatever the app's
  language, and are set left to right. They are legal texts in the words
  their authors chose.
- The list is in alphabetical order after Cubeulator's own row, and
  differs per platform: a build lists only what that build ships. The
  bundled fonts are components and are listed.
- A long text is one scrolling block. A screen reader reads it as plain
  text and can move through it by paragraph.

## States

### `licences.list`

The introduction, then the rows. A row: to `licences.detail` for that
component. Back: to About.

### `licences.detail`

The component's name as a heading, its licence identifier beneath, then
its notice in full. The top bar's title stays "Licences". Back: to
`licences.list`, at the scroll position it was left.

### `licences.unavailable`

The generated notices could not be loaded: the resource is missing or
unreadable. A caution notice says so and gives the address where the same
notices are published with the source (`licences.unavailable.body`, `%1`).

This should never happen in a build that passed its tests, and a test
asserts it. It is designed because shipping a build with no way to read
the notices would break the licences it is built on.
